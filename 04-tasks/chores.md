- [x] Narrow a bare `except:` to `except Exception:` in `utils.py`'s `_parse_malformed_frontmatter()` (pre-existing style guide violation, fixed while already editing the file).
- [ ] Make `BloggerAPI` (`blogger_api.py`) resolve its content directory the same volume-first way `get_content_directory()` (`server.py`) and `SiteGenerator` (`generator.py`) already do. Currently `BloggerAPI.blog_dir` is hardcoded to `/app/content/blog` (never checks `/data/content`), so (a) a post edited via the web admin — which writes only to `/data/content` — is invisible to MarsEdit until the next scheduled GitHub sync, and (b) a container restart between a MarsEdit edit and the next MarsEdit read reverts `/app/content` to the last-pushed GitHub commit via `startup.sh`'s `git checkout -f`, showing MarsEdit a stale post even though `/data/content` (and the live site) have the current one. Reported by the user as "MarsEdit shows an older copy even after a refresh." Fix touches `__init__`, `blogger_newPost`, `blogger_editPost`, `blogger_deletePost`, `metaweblog_newMediaObject`; should also let `_backup_to_volume`/`_delete_from_volume` be deleted entirely once writes go straight to the volume. Proposed, not yet approved.
