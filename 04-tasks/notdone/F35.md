# Tasks for Feature F35

## T01 — Read GIT_TOKEN from environment at sync time
**Status**: not done
**Description**: In `src/salasblog2/scheduler.py` (or wherever `sync_to_github()` is implemented), reconstruct the git remote URL from the current value of `os.environ.get("GIT_TOKEN")` at the moment of each sync call, rather than relying on a URL baked in at startup. Pattern: `url = f"https://{token}@github.com/{repo}"` then `git remote set-url origin {url}` before `git push`. This ensures a rotated token takes effect immediately without a redeploy.

## T02 — Add fallback error message for 403 / auth failures
**Status**: not done
**Description**: In the git sync error path, detect when the push fails with a 403 or "authentication failed" message and surface a clear admin-facing error: "Git push failed: authentication error. If you recently rotated GIT_TOKEN via `fly secrets set`, the new token is now active — retry the sync." Log at ERROR level with the full stderr for diagnostics.

## T03 — Write tests for dynamic token reconstruction
**Status**: not done
**Description**: Add `tests/test_scheduler_git_sync.py`. Test that: (1) `sync_to_github()` reads `GIT_TOKEN` from `os.environ` at call time, not at import/startup time; (2) changing `os.environ["GIT_TOKEN"]` between calls causes the new token to be used; (3) a missing `GIT_TOKEN` produces a clear error rather than a silent 403. Use `unittest.mock.patch.dict(os.environ, ...)` and mock `subprocess.run`.
